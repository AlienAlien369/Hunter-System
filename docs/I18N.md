# Languages (i18n)

Hunter System ships in **English**, **Hindi** (Devanagari) and **Hinglish** (Hindi in Latin letters).
`src/i18n` is a small, typed layer; adding a language is one file and one table row.

## How it works

- `src/i18n/messages/en.ts` is the source of truth. Its keys define the `MessageKey` type.
- `hi.ts` and `hinglish.ts` are typed `Messages`, so a missing or extra key is a compile error.
- English is bundled. Other languages are **loaded on demand** (`loadLocale`), so English visitors never download them.
  A returning Hindi/Hinglish hunter's language is fetched before the first paint, so English never flashes.
- Components call `const t = useT(); t('dash.welcome', { name })`. Code outside React uses the exported `t(...)`.
- Plurals use ICU categories through `translatePlural(locale, 'wr.nQuests', n)` with `_one` / `_other` keys.
- Dates, numbers and money always go through `formatDate`, `formatNumber`, `formatCurrency` (never `toLocaleString` with a hard-coded locale).

## Add a language

1. Create `src/i18n/messages/<code>.ts` exporting a `Messages` object (copy `hinglish.ts` and translate).
2. Add a row to `LOCALES` in `src/i18n/index.ts`:
   `{ code, label, lang, intl, dir, messages: en, load: () => import('./messages/<code>').then(m => m.<name>) }`.
   Use `dir: 'rtl'` for right-to-left scripts; `<html dir>` follows it.
3. Run `npm test`. The tests check every key exists, placeholders (`{name}`) match English, no stray whitespace, and the script is right.

## House style

- **Hindi:** friendly "तुम" in the app (the audience is mostly students). Formal "आप" only where parents or legal text are read
  (`pay.*`, `parent.*`, `legal*`, `landing.parents*`). A test enforces this.
- **Hinglish:** casual "tum/karo", Latin letters only. Keep English product nouns (quest, XP, streak, rank).
- Keep the brand name "Hunter System" and "XP" untranslated. Do not use third-party franchise names in any language.
- Keep strings short; avoid joining sentence fragments in code. For bold fragments use `[[like this]]` and split in the component.

## What is not translated (yet)

- Content that comes from the server in English: hidden-quest titles, XP-change explanations in the routine dialog,
  AI-written text other than the weekly coach (which writes in the hunter's language via an allowlisted `language` field).
- The Admin page (owner only), the content-creation module view, and the DSA / SaaS / nutrition / system-design module pages.
- The shareable Hunter card image (kept in English so fonts always render).

## Push notifications

Push subscriptions store an allowlisted `locale`; the 8pm streak nudge and the Monday recap are written server-side in that
language (`server/src/push.ts`). Switching language re-saves the subscription.
